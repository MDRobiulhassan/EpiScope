# EpiScope Data Dictionary and Provenance

## Dataset inventory

| Dataset | Path | Source and purpose |
|---|---|---|
| Encounter input | `data/bronze/encounters/encounters.csv` | Synthetic batch encounter records created by `generator/generate_encounters.py`. |
| Facility registry | `data/bronze/facilities.csv` | Synthetic registry of 600 facilities, including district, facility type, bed count, and ICU bed count. |
| Outbreak windows | `data/bronze/ground_truth_outbreaks.csv` | Synthetic outbreak windows used only for evaluation. |
| Bronze encounters | `data/bronze/encounters_parquet/` | Encounter source fields plus `_source_file` and `_ingested_at` metadata. |
| Silver encounters | `data/silver/encounters/` | Validated encounter rows; the raw `patient_id` is dropped after hashing. |
| Encounter quarantine | `data/silver/quarantine/` | Encounter rows with one or more validation failures, including their internal patient ID. Keep this dataset restricted. |
| Quality report | `data/silver/quality_report/` | Counts by implemented Silver rule. Rule counts may overlap when a row fails multiple checks. |
| Incremental inventory CSV | `data/incremental_drop/inventory_snapshot.csv` | One synthetic daily facility stock and bed-occupancy feed generated by `generator/generate_inventory_drop.py`. |
| Bronze inventory | `data/bronze/inventory_snapshots/` | Idempotently appended snapshots, keyed by `(snapshot_date, facility_id)`, with ingestion metadata. |
| Silver inventory | `data/silver/inventory_snapshots/` | Inventory snapshots passing date, facility, numeric, and bed-capacity checks. |
| Inventory quarantine | `data/silver/inventory_quarantine/` | Inventory rows failing one or more implemented checks. |
| Gold inventory | `data/gold/daily_inventory_by_district/` | Daily district totals for stock and occupied/total beds, with a derived bed-occupancy rate. |
| Gold encounter outputs | `data/gold/` | Aggregated encounter data used by the analytics modules. See each module for its exact schema. |
| Public case data | `data/public/daily_cases/` | Aggregated public data prepared with the documented small-count suppression policy. |
| Dashboard JSON | `dashboard/data/*.json` | Exported cases, alerts, forecasts, resources, and calendar data consumed by the dashboard. Case counts are aggregated to district-disease-week before applying the 1-4 suppression rule. |

## Encounter fields

The synthetic encounter generator writes these fields. Spark infers source types when reading the CSV; normalized types are shown below.

| Field | Type | Meaning | Source / handling |
|---|---|---|---|
| `encounter_id` | integer | Encounter record identifier. | Generated; 2% of generated rows may reuse an earlier ID to model resubmissions. |
| `patient_id` | string | Synthetic patient identifier. | Generated; hashed in Silver and removed from clean output. It remains in restricted Bronze and quarantine data. |
| `facility_id` | string | Facility reference. | Generated from the synthetic facility registry. |
| `onset_date` | date | Synthetic symptom onset date. | Generated within 2021-2025. |
| `report_date` | date | Synthetic date reported. | Onset date plus a generated reporting delay. |
| `encounter_date` | date | Date assigned to the synthetic encounter. | Generated within 2021-2025 and used in Gold aggregations. |
| `district` | string | Bangladesh district label. | Generated from the project's 64-district list. |
| `disease` | string | Synthetic disease category. | Dengue, diarrhoea, malaria, respiratory infection, or typhoid. |
| `icd10_code` | string | Disease code used by this generator. | Generated mapping; Silver checks consistency with the disease category. |
| `age` | integer | Synthetic age in years. | Generated; invalid values are deliberately injected. |
| `sex` | string | Synthetic sex category. | `F`, `M`, or `X`. |
| `severity` | string | Synthetic severity. | `mild`, `moderate`, or `severe`. |
| `temperature_c` | number | Synthetic temperature-like value. | Generated value; it is not a verified weather observation. |
| `rainfall_mm` | number | Synthetic rainfall-like value. | Generated value; it is not a verified weather observation. |
| `lab_confirmed` | boolean | Synthetic lab-confirmation flag. | Generated. |
| `admitted` | boolean | Synthetic admission flag. | Generated from severity and a probability. |
| `outcome` | string | Synthetic outcome. | `recovered` or `deceased`. |
| `synthetic_outbreak` | boolean | Synthetic outbreak-window label. | Evaluation ground truth; must not be presented as detector input. |
| `source` | string | Record provenance label. | `synthetic` for encounter-generator rows. |
| `patient_id_hash` | string | SHA-256 hash of the patient ID with the configured salt. | Added in Silver; the salt is supplied via `EPISCOPE_HASH_SALT`, not stored in the repository. |
| `_source_file` | string | Input file path recorded by Spark. | Added in Bronze. |
| `_ingested_at` | timestamp | Ingestion timestamp. | Added in Bronze; it changes on a newly ingested batch. |

## Incremental inventory fields

`generator/generate_inventory_drop.py` reads facility IDs, districts, and bed capacities from the generated facility registry. It writes one row per facility for the selected snapshot date. Stock values and occupancy are deterministic for a fixed seed and registry.

| Field | Type | Meaning |
|---|---|---|
| `snapshot_date` | date | Date represented by the daily feed; part of the idempotency key. |
| `facility_id` | string | Facility identifier; part of the idempotency key. |
| `district` | string | Facility district from the synthetic registry. |
| `total_beds` | integer | Facility bed capacity from the registry. |
| `occupied_beds` | integer | Synthetic occupied beds, constrained to the facility capacity. |
| `iv_saline_units` | integer | Synthetic available IV saline units. |
| `ns1_test_kits` | integer | Synthetic available NS1 test kits. |
| `ors_sachets` | integer | Synthetic available oral rehydration sachets. |
| `antimalarial_courses` | integer | Synthetic available antimalarial courses. |
| `source` | string | `synthetic_incremental`. |
| `_source_file` | string | File path recorded at Bronze ingestion. |
| `_ingested_at` | timestamp | Ingestion timestamp recorded at Bronze ingestion. |

The inventory pipeline appends only keys not already present in Bronze. Replaying the same snapshot therefore appends zero rows. Spark outputs are staged locally and copied to the configured data paths after file-size checks. A corrected record for an already ingested `(snapshot_date, facility_id)` is currently treated as a replay and is not applied; late revisions/upserts are not implemented.

## Provenance and privacy

Encounter, outbreak, facility, and inventory values are synthetic. The generator's temperature and rainfall fields are not sourced from weather stations. Historical experiment metrics are recorded project results; refer to `docs/technical/EXPERIMENTS.md` for their evidence and limitations.

Patient identifiers remain in internal Bronze and quarantine outputs. Restrict access to these paths. Clean Silver data contains a salted hash rather than the raw patient identifier. Public dashboard exports are aggregated; suppressing counts from one through four does not guarantee protection against inference from related totals or views.

For the exact field names consumed or exported by an analytics stage, consult that stage's source and the corresponding JSON export. This dictionary should be revised when those schemas change.
